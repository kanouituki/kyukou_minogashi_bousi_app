---

## 2. 課題とアイデアの背景
- **日常の課題**: 学生が休講情報を見逃して無駄に登校してしまう問題
  - KLMSのお知らせを毎朝チェックする習慣がない
  - 休講情報が授業直前に投稿されることもある
  - せっかく登校したのに休講だった時の時間・交通費の無駄
- **ユビキタス技術でのアプローチ**:
  - 位置情報（GPS）で「家を出る」タイミングを検知
  - KLMSと連携して自動的に休講情報を取得
  - GPT-4による自然言語解析で休講判定を自動化
- **選定理由**: SFC学生として実際に経験した身近な問題を技術で解決したい

---

## 3. アプリ概要・利用シーン
- **実現内容**: 「家を出る前に休講情報を自動チェックし、無駄な登校を防ぐアプリ」
- **想定ユーザー**: SFC学生（特に遠方から通学する学生）
- **利用シナリオ**:
  1. 事前準備：アプリにCanvas APIトークンを登録
  2. 日常利用：
     - 朝、家を出ようとする
     - アプリが位置情報から移動を検知
     - 「休講情報」ボタンをタップ
     - KLMSから最新の休講情報を自動取得
     - 休講がある場合は画面に表示
     - 登校を中止して時間を有効活用

---

## 4. 当初の計画 vs 実装結果（対比）

### 当初の計画（左側）
- バックグラウンド位置監視
- 自動プッシュ通知
- keio.jpスクレイピング連携
- 体育・補講情報も取得
- OAuth認証でKLMS連携

### 実際の実装（右側）
- 手動での休講チェック
- アプリ内表示（通知なし）
- Canvas API直接連携のみ
- 通常授業の休講情報のみ
- APIトークン手動入力方式

### 変更理由と判断
- **技術的制約**: バックグラウンド処理はOSの制限が厳しく断念
- **開発期間**: 限られた時間で確実に動作する機能を優先
- **API制限**: keio.jpはスクレイピング対策があり、Canvas APIに集中
- **工夫点**: GPT-4による自然言語解析で、様々な形式の休講お知らせに対応

## 5. 技術要件への対応（ハイライト）
- それぞれの技術要件にどう対応したかを**視覚的に提示**（図解・ラベルなど）

| 技術項目 | 実装内容・対応方法 |
|----------|----------------------|
| **センシング** | GPS位置情報を取得、緯度・経度を記録<br>Unity LocationServiceでリアルタイム更新 |
| **認識** | ヒュベニの公式で移動距離を計算<br>「家からの距離」で外出状態を推定 |
| **通信** | UnityWebRequestでHTTP通信実装<br>FastAPIサーバーとRESTful API連携 |
| **ChatGPT API** | お知らせタイトル・本文をGPT-4で解析<br>休講判定・日時抽出を自動化 |

## 6. システム構成・使用技術

### システム構成図
```
┌─────────────────┐         ┌─────────────────┐
│  Unity アプリ    │  HTTP   │  FastAPI サーバー │
│  (Android/iOS)   │ ------> │  (Python)        │
│                  │ <------ │                  │
└─────────────────┘         └────────┬────────┘
        │                            │
        │ GPS                        │ API
        ↓                            ↓
  ┌─────────────┐            ┌──────────────┐
  │ 位置情報取得 │            │ Canvas LMS   │
  └─────────────┘            │ OpenAI GPT-4 │
                              └──────────────┘

API返却情報:
- Canvas API: コース情報、お知らせ一覧（タイトル・本文・投稿日時）
- GPT-4 API: 休講判定結果、対象科目名、休講日時、休講理由
```

### 使用技術スタック
#### クライアント側（Unity）
- **開発環境**: Unity 2022.3.24f1
- **言語**: C# (.NET Standard 2.1)
- **フレームワーク**: GameCanvas
- **主要機能**: LocationService, UnityWebRequest
- **対応OS**: Android/iOS

#### サーバー側（Python）
- **言語**: Python 3.11+
- **フレームワーク**: FastAPI
- **APIクライアント**: Requests, OpenAI SDK
- **デプロイ先**: SFC CCX03サーバー (133.27.4.213)

## 7. 実装機能・デモ

### 実装済み機能
1. **位置情報記録・測定**
   - リアルタイムGPS取得
   - 記録地点からの距離計算
   - 移動検知機能

2. **Canvas API連携**
   - APIトークン安全管理（マスク表示）
   - コース一覧取得
   - お知らせ自動取得

3. **休講情報解析・表示**
   - GPT-4による自然言語解析
   - 休講判定・日時抽出
   - 見やすいリスト表示

### デモのハイライト
- **位置記録デモ**: 「位置記録」ボタンで現在地を保存、距離をリアルタイム表示
- **API設定デモ**: トークン入力時のセキュアなマスク表示
- **休講取得デモ**: ボタン一つでKLMSから最新情報を取得・解析・表示
  - 「休講情報: 2件の休講があります」
  - 科目名・日時・理由を整理して表示

## 8. 苦労・工夫・学び

### 技術的な苦労点
- **Unity-サーバー間の非同期通信**
  - コルーチンとコールバックの組み合わせで解決
  - エラーハンドリングの実装が複雑だった
  
- **GPT解析の精度向上**
  - 様々な形式の休講お知らせに対応するプロンプト設計
  - 日付・時限の抽出パターンを試行錯誤

### 工夫点
- **セキュリティ**: APIトークンをマスク表示し、安全に管理
- **UX設計**: シンプルな3ボタンインターフェースで操作を簡潔に
- **キャッシュ機能**: サーバー側で既読管理し、新着のみ解析

### 学んだこと
- **ユビキタス技術の実践**: センシング→認識→アクションの流れを実装
- **API連携の重要性**: 既存サービス（KLMS）との統合で価値を創出
- **プロトタイピング**: 完璧を求めず、動くものを作ることの大切さ
